# SAKE LENS / 開発者ガイド

## 設計方針

日本酒の画像から用語の位置を見つける処理と、用語を説明する処理を分けています。文字認識はブラウザ内の機械学習OCR、説明と追加質問への回答はDocker内のローカルLLMが担当します。

RAGおよびファインチューニングは使用していません。`src/glossary.js`は用語名・別名・分類の照合リストです。説明文や検索文書をLLMへ渡す用途はありません。照合リストにない語は、OCRで読めても説明ボタンの対象にはなりません。

## 使用技術

| 技術 | 用途 |
| --- | --- |
| React / JavaScript | 画像表示、用語ボタン、会話状態の管理 |
| Vite | 開発用サーバー、本番の静的ファイル生成 |
| Canvas API | 画像の反転・二値化 |
| Tesseract.js | 学習済みモデルによる文字認識と座標取得 |
| jpn / eng / jpn_vert | 日本語・英語・日本語縦書きのOCRモデル |
| Ollama / gemma3:4b | 用語説明と履歴付きチャット |
| Nginx | 静的配信、Ollamaへのリバースプロキシ |
| Docker Compose | アプリ、LLM、モデル取得処理の起動 |
| Lucide React | UIアイコン |
| Sharp | Node.jsでの実画像OCR回帰検証用の前処理 |

DockerビルドではNode.js 22 Alpine、配信にはNginx 1.27 Alpine、Ollamaには0.12.0を指定しています。JavaScript依存の多くは現在`latest`指定です。再現可能なビルドに向けたバージョン固定は今後の課題です。

## 処理の流れ

1. 利用者が画像を選択し、ブラウザ内に読み込みます。
2. 元画像を横書き向けに、反転画像と二値化画像を縦書き向けに順番にOCRします。
3. 隣接する文字の座標を比較して、最大12個の認識単位を連結します。
4. 用語リストと一致する候補を選び、重なる領域では長い用語を優先します。
5. 元画像の座標を表示サイズに対する割合へ変換し、説明ボタンを配置します。
6. 用語を選ぶと、その用語についての質問をOllamaへ送信します。
7. 追加質問は、それまでの会話履歴とともに同じチャットAPIへ送信します。

白文字向けの前処理は輝度を反転し、反転後の値65を境に二値化します。固定しきい値なので、あらゆる背景・照明に適応するものではありません。

## コンテナ構成と通信

| サービス | 責務 | 保存・公開 |
| --- | --- | --- |
| app | Viteビルド済みファイルをNginxで配信 | ホストの8080番ポート |
| ollama | モデルのロードと推論 | モデルはollama-dataボリュームへ保存 |
| model-loader | gemma3:4bを取得して終了 | ollamaサービスへ内部接続 |

ブラウザの`POST /ollama/api/chat`をNginxが`ollama:11434/api/chat`へ転送します。リクエストにはモデル名、システム指示、会話履歴を含め、`stream: false`で回答完了を待ちます。

Ollamaのポートをホストへ直接公開する設定はありません。ただし、appの8080番ポートは現在localhost限定ではなく、認証も未実装です。個人のローカル環境を前提とした構成です。

画像はOCRのためにサーバーへアップロードしません。用語と会話文はOllamaへ送信します。OCR実行用データやモデルの初回取得にはネットワーク接続が必要で、完全オフライン配布には対応していません。

## 状態とエラー処理

設定画面で説明・チャットの言語（日本語が初期値、英語・簡体字中国語・韓国語）と普段飲んでいるお酒（最大500文字）を指定できます。画面UIの言語は日本語です。設定はlocalStorageのsake-lens.preferencesに保存し、読み込み失敗時は日本語・未入力に戻します。普段のお酒はLLMへの指示に含め、初回説明で比較例を入れるようにします。未入力時は好みを仮定しません。意味のある比較が難しい場合は無理に例えないよう指示しています。

- 画像・検出結果・会話はフロントエンドのメモリ上で管理します。
- チャットを閉じると会話履歴を破棄します。履歴の永続保存はありません。
- 説明取得に失敗した場合はエラーと再試行を表示します。辞書説明へのフォールバックはありません。
- チャット通信は180秒でタイムアウトし、閉じる際も通信を中断します。
- モデル名は設定画面から変更できます。モデルの取得は別途必要です。

## 起動と停止

Docker EngineとDocker Composeを利用できる環境で、リポジトリルートから実行します。

```bash
cd app
docker compose up -d --build
```

初回はモデル取得に時間がかかります。appが起動していても、モデル取得が終わるまではチャットが利用できない場合があります。

```bash
docker compose ps
docker compose logs --tail=20 model-loader
docker compose exec ollama ollama list
docker compose down
```

通常の`down`ではモデル用ボリュームが残ります。Composeのプロジェクト名は、フォルダー移動前のモデルを引き継ぐため`a`に固定しています。

GPU割り当ては未設定です。CPUでの応答速度は環境に依存します。

## 開発と検証

以下は`app`ディレクトリで実行します。

```bash
npm install
npm run dev
npm run build
```

開発画面は http://localhost:5173 で開きます。`/ollama/`へのリクエストは、ViteからDocker版アプリの http://localhost:8080 へ転送します。LLMを使う場合は、先に別のターミナルでDocker構成を起動してください。

```bash
docker compose up -d --build
npm run dev
```

Viteの設定を変更した場合は、起動中の`npm run dev`を一度終了して再起動してください。

実画像のOCR回帰検証:

```bash
node test-ocr.mjs <画像パス>
```

このスクリプトは「純米大吟醸」の検出を成功条件にしています。任意画像の認識精度を測る汎用テストではありません。検証に使った画像はリポジトリに同梱していないため、対象画像を別途指定します。

確認済みの範囲は、指定された広告画像からの「純米大吟醸」と座標の抽出、本番ビルド、OllamaチャットAPIの会話履歴付き応答です。ブラウザ上の一連の操作を自動検証するE2Eテストは未整備です。サンプル画像の初期ボタンは固定座標を使うため、サンプルを開くだけではOCRの検証になりません。
